# Einheitliche Temperaturquellen-Integration (Branch, nicht veröffentlicht)
Testversion integration-02. Standard: interner Temperatursensor. PTC und EOC sind Beta-Optionen im selben geführten Ablauf; kein Router, Seitenwechsel, USB-Trennen oder separater Speicher. Standard-Algorithmus calibration.js bleibt unverändert; temperature-source-dispatch.js wählt den erweiterten Fit nur bei homogenen PTC/EOC-Messpunkten und die erweiterte Vorabprüfung nur bei bestätigtem Temperaturprofil.
Die Auswahl allein ändert keine Chipregister. Bei Rückkehr nach bereits angewendetem Beta-RAM-Profil wird bei identischer UID/Session/NVM die gesicherte RAM-Konfiguration rückgelesen wiederhergestellt; keine NVM-Schreiboperation. Ein dauerhaft umprogrammierter Sensor benötigt einen passenden Chipmodus. Bei Quellenwechsel mit Messdaten ist eine Bestätigung erforderlich. Keine automatische Pin- oder Boot-Umschreibung.
Start: Branch herunterladen, im Ordner python3 -m http.server 8000, Chrome/Edge http://localhost:8000/index.html. Demo: ?demo=1. Standard und Beta wählen in Schritt 3. Keine Produktionsfreigabe. Native DLL-Neuausführung, Browser-End-to-End, reale SSP3/ESP32- und NVM-Kaltstarttests bleiben Abnahmepunkte.
Tests: node tests/temperature-source-dispatch.test.cjs und node temperature-beta/manufacturer-audit.cjs.

Zusätzlicher Demo-Regressionsvergleich: `node tests/temperature-source-demo.test.cjs`. 189 Standard-Demo-Registerabfragen sowie PTC/EOC-Quellenwechsel und Rückkehr zum ursprünglichen Demo-RAM (237 Prüfungen insgesamt). 2 vollständige Standard-NVM-Abbilder werden verglichen. Die Regressionen sind kein Hardwaretest.

Integration 03: Kein fest hinterlegter ADC-Richtwert von ±25’000. Digitale Sättigungshinweise nur an −32’768 / +32’767, keine Aussage zur analogen Linearität. Prognosewarnungen nur bei Überschreiten der digitalen Grenzen. DSP-Vorgabe ±32’000 (bisheriger Standard), individuell veränderbar. Historisches Rechenbeispiel in DSP-Dokumentation ausdrücklich nicht freigegeben. 25 kBd bleibt unverändert.
